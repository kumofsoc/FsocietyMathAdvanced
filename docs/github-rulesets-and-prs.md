# MathMaMath: импорт GitHub Rulesets и обработка Pull Requests

## Импорт правил (активировать вручную)

JSON-файлы, помещённые в репозиторий, **не активируют защиту автоматически**. Для импорта необходим доступ к Settings репозитория.

1. Откройте [Settings → Rules → Rulesets](https://github.com/kumofsoc/MathMaMath/settings/rules).
2. Выберите **New ruleset → Import a ruleset**.
3. Загрузите файл `.github/rulesets/protect-main.json`, проверьте настройки, нажмите **Create**.
4. Повторите для `.github/rulesets/protect-version-tags.json`.
5. Убедитесь, что в списке оба ruleset имеют состояние **Active**, а ветка `main` действительно защищена.

Правила для `main`:
- запрет удаления и force push, линейная история, слияние только через PR и **squash**;
- разрешение слияния только после проверок **build**, **CodeQL (JavaScript / TypeScript)**, **Review new dependencies**, **gate**;
- обязательное разрешение обсуждений в PR;
- число обязательных approvals = **0**, чтобы не заблокировать репозиторий с одним поддерживающим аккаунтом. Когда появится независимый reviewer, установите 1 и включите CODEOWNERS по необходимости;
- требование актуальной ветки: `strict_required_status_checks_policy=true`. Устаревшие PR перед слиянием нужно обновить от `main`.

Правила для `refs/tags/v*` защищают уже созданные релизные теги от удаления и принудительного перемещения, не запрещая создание новых релизов.

В шаблонах отсутствуют bypass-исключения: никто не получает автоматического обхода. До активации проверьте, что у аккаунта есть возможность создавать PR и запускать CI. При ошибке в названиях checks ruleset может заблокировать слияние: сравните точные имена в [Actions](https://github.com/kumofsoc/MathMaMath/actions) и поправьте ruleset в Settings.

Примечание: GitHub не применяет `.github/rulesets/*.json` автоматически при пуше. Для пользователей с правами администратора доступны также REST API и `gh api`:

```bash
gh api --method POST repos/kumofsoc/MathMaMath/rulesets --input .github/rulesets/protect-main.json
gh api --method POST repos/kumofsoc/MathMaMath/rulesets --input .github/rulesets/protect-version-tags.json
```

Используйте **либо импорт через UI, либо API**: оба способа создают правила, и не следует дублировать их.

## Очистка списка PR

Старые PR не следует автоматически сливать только потому, что CI исторически был зелёным. Для обновлений зависимостей нужно проверить совместимость, прогнать CI с актуальной базой и при изменениях графики провести визуальную проверку.

- Отдельные Dependabot PR для новых major-версий React-анимаций, KaTeX, TypeScript, Vite и Three.js требуют индивидуальной проверки и не вливаются вместе.
- Бывшие PR со старыми версиями Actions заменяются обновлением текущего `release-gate.yml`; после слияния замещающего изменения их можно закрыть как superseded.
- Старые крупные архитектурные PR не следует вливать повторно поверх актуального приложения; сравнивайте их с `main` и переносите необходимые отдельные исправления заново.

Не переписывайте историю `main`, чтобы «очистить» старые PR. Закрытие PR не удаляет ветку и коммиты. Мержите только ветки с прошедшими проверками.
